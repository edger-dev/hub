# Spec — nodes reverse-dial and reconnect forever

**Contract.** A node never listens for the hub to reach in. Every node dials
*out* to the hub and keeps retrying with backoff until the hub answers — and,
once connected, re-dials on any disconnect, forever. A node therefore needs a
hub configured; with none it is a hard startup error, not an idle wait (§2.4).

**Chosen.** Out-dialing with unconditional reconnect as the node's baseline
operational assumption. A hub restart, a sleeping hub host, a crash, or a deploy
all reduce to the same transient — "the hub blinked" — from which the node
recovers on its own. This is what makes self-restarting hub deploys survivable
(§5) and lets every node, including ones behind NAT, be a plain outbound dialer.

**Rejected.** The hub dialing *into* nodes (inbound listeners per node). It needs
a firewall/port-forward story per node and defeats the sleep/restart tolerance
the out-dial model buys. Also rejected: giving up after N retries — the loop is
*forever*, since the hub is expected to come and go.

**Escape hatch.** Backoff is bounded (a cap between attempts), so "forever" is
patient, not a hot loop; a caller may still tear the node down by dropping it.
