# Finding — a vox channel only delivers once bound through a call

**Observed** (vox 0.10.0-rc.5 / vox-types, while building the hub's discovery
fan-out, M3 §2.6).

`vox_types::channel::channel::<T>()` hands back a `(Tx<T>, Rx<T>)` pair, but the
pair does **not** work as a local queue. Values move only after the framework
*binds* the handle, which happens when that handle is passed in an RPC method's
**arguments**. A locally created pair, never passed through a call, stays
unbound: `Tx::send(..).await` blocks forever rather than erroring.

This is documented on `channel()` ("the framework binds the handle that appears
in the args… do not simulate request/response by pairing two channels") — worth
restating because the failure mode is a silent hang, not a type error or a
`Result::Err`.

**Impact.** Any hub-side type that fans out to `Tx` channels cannot have its
*delivery* unit-tested with a synthetic pair; the test hangs until the harness
timeout. Test such code end-to-end through a real call that supplies the channel
(e.g. `ConsumerApi::subscribe_topology`), and keep unit tests to bookkeeping.
