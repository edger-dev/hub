# Spec — structured live session diagnostics

**Contract.** An authenticated `DiagnosticsApi` reports why a session is or is
not reachable without requiring host logs. It exposes protocol capabilities,
peer registration direction/generation/current state, and a real
`session_probe` for a local or one-hop peer target. The API uses the existing
consumer authentication and never exposes private keys, tokens, or unnecessary
workspace metadata.

A probe is evidence-first: it attempts the target callback and records the
observed result, then adds registration evidence that explains it. Every report
contains a probe id, timestamp, source, target, elapsed time, and checks with a
stage, status, and sanitized detail. Statuses are `ok`, `failed`, `unsupported`,
and `unknown`; an old hub or shim is `unsupported`, not offline. A listing is a
registration snapshot, not proof of reachability.

`SessionService.ping` returns basic session identity and protocol version
without touching the mailbox or claiming delivery health. Callback failure,
authentication failure, unknown target, and timeout remain distinct. Reports
are snapshots, not guarantees after reconnect. No multi-hop probe, persistent
history, mailbox admission check, or automatic remediation is offered in this
contract.

**Why.** Peer registration can be stale while a session still appears listed.
Operators and agents need the failing hub, stage, and registration generation
without guessing from a flat `session_list` or parsing free-form errors.

**Rejected.** Public unauthenticated diagnostics, treating ping as mailbox
proof, durable diagnostic logs, dashboard-first design, and automatic restart
recommendations.

**Escape hatch.** Capability negotiation, bounded transition history, mailbox
admission probes, console views, and telemetry export can be added without
changing the report's evidence model.
