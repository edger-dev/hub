# Spec — live node discovery from the reverse-dial registry

**Contract.** The hub reports which nodes are connected **right now**, derived
from the registry it already maintains from reverse-dialed connections (§2.1).
A consumer reads a `TopologySnapshot` and may subscribe to a tail of
`TopologyEvent`s; applying the tail to the snapshot keeps its view current. There
is no separate registration protocol and no static node list.

**Chosen.** Discovery as a *projection of live connections*. A node appears when
its first link registers and disappears when its last link drops, so the reported
topology cannot describe a node that is not actually reachable.

**Rejected.** A static list baked into the console (or a config file). It drifts
in both directions: a newly added node stays invisible, and a dead node keeps
looking alive — the two failure modes an operator most needs discovery to
prevent.

**Escape hatch.** Node auth, ACLs, and an offline/expected-node inventory are
explicitly out of scope until needed; the registry answers "who is connected",
not "who should exist".
