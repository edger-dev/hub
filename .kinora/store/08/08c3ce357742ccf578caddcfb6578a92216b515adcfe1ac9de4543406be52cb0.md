# Spec — one node, many links

**Contract.** One machine is one *node* (stable `NodeId`) that may register more
than one *link* (`LinkLabel`) — e.g. a default `stable` link and a session-scoped
`dev` link with its own toolchain. A consumer targets a node plus an optional link
(`LinkSelector`); the hub routes to the selected link, defaulting to `stable` and
falling back to `stable` when the requested link is absent.

**Chosen.** The *link* as the axis of variation under a stable *node* identity.
Reads/observe operations are link-agnostic (any link backs shared node state);
`start`-type operations are link-scoped (they carry that link's toolchain).

**Rejected.** "One link per node" — cannot isolate dev churn from stable node
infrastructure. And "a distinct node *name* per link" — breaks shared per-node
state, since the two links would no longer be recognised as the same node.

**Escape hatch.** A node with a single `stable` link is the degenerate case and
needs no link label from callers (`LinkSelector` with `link: None`).
