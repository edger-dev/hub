# Spec — WebSocket listener exposes a shallow healthcheck

**Contract.** `GET /healthz` on the hub's WebSocket listener returns `200 OK`
with a short plain-text body and no hub topology, session, or credential data.
Other ordinary non-WebSocket HTTP requests return `426 Upgrade Required` rather
than a proxy-visible `502 Bad Gateway`. Valid WebSocket handshakes retain their
existing Vox behavior.

The healthcheck proves only that the HTTP listener and its immediate response
path are alive. End-to-end authentication, peer discovery, and routing require a
real authenticated MCP `session_list` or another API call; `/healthz` does not
prove them.

**Why.** Caddy and uptime checks need an explicit success response instead of
treating the expected WebSocket-only rejection as a service failure. The public
endpoint remains intentionally shallow and unauthenticated because it reveals
nothing beyond availability.

**Escape hatch.** A later authenticated deep-health endpoint can report protocol
and peer status without changing the shallow probe.
