## Phase 1 — the registry (pure, no transport)

- Create `crates/hub` (lib), add to workspace `members`; drop
  `tests/architecture.rs`.
- `Registry` keyed `(NodeId, LinkLabel)` over a generic per-link value, so the
  logic is testable before a vox client exists.
  - `register` — insert or replace; a known pair is accepted churn (§2.4).
  - `remove` — drop one link; the node vanishes with its last link (§2.6).
  - `resolve(&LinkSelector)` — requested link, else `stable`, else
    `UnknownLink`; `UnknownNode` when the node has no links (§2.5).
  - `snapshot()` — a `TopologySnapshot` of what is connected (§2.6).
  - Each mutation reports the `TopologyEvent`s it implies (node vs link
    connect/disconnect) so the tail is derived from one source of truth.
- Unit tests for every rule above, including the fallback ladder.

*Status:* **done** (commit 345c195) — Registry<T> over BTreeMap; all 11 rules
tested (first/additional link events, reconnect churn silent, node vanishes with
last link, default-to-stable, explicit link, stable fallback, UnknownLink,
UnknownNode, snapshot). hub-protocol identity types gained Ord to key the map.

## Phase 3 — vox wiring + real-node end-to-end

- `NodeIngress` impl: a per-connection handler that, on `register`, opens a
  `NodeServiceClient` back to the caller and stores it in the registry. **Probe
  first**: the dispatcher is built *before* `establish_connection()` returns the
  handle, so the callback route needs a shared slot (or an equivalent seam) —
  confirm the mechanism with a spike before writing the impl.
- `ConsumerApi` impl: `topology`, `subscribe_topology`, and `route` — resolve the
  link, call the node's `deliver`, map failures to `RouteError::Hub` vs
  `RouteError::Node`.
- End-to-end test: the real `node` crate dials the real hub, registers, shows up
  in `topology`, and answers a consumer's `route` call.
