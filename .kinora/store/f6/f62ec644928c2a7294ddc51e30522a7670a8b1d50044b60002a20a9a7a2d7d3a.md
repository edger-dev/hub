Dispatch first (connector-agnostic), then one real connector, then prove it
through the whole mesh.

## Phase 1 — the connector trait + registry

- `Connector` trait: `descriptor()` (id + kind, for `Registration`) and
  `call(method, payload) -> Result<Vec<u8>, NodeError>`.
- `Connectors` registry: register by id; dispatch a `RoutedCall` to the addressed
  connector; unknown id → `UnknownConnector`.
- `StubNode` becomes `NodeDaemon` holding the registry; `deliver` dispatches, and
  a node with no connectors still answers `UnknownConnector` (today's behaviour,
  now for the right reason).
- `NodeConfig::connectors` is derived from the registry so discovery advertises
  what the link can actually do (§2.6).
- Unit tests: dispatch hits the right connector; unknown id/method refuse.

*Status:* not started.

## Phase 2 — the reference `files` connector

- Rooted at a configured directory. Methods: `list` and `read`.
- Payloads are facet types encoded as JSON — the connector owns the codec, the
  hub never sees inside (§1).
- **Refuses to escape its root** (`..`, absolute paths, symlink-ish traversal):
  covered by tests, because a file connector that can be talked out of its root
  is a hole, not a feature.

*Status:* not started.

## Phase 3 — end-to-end through the hub

- A consumer routes `files.read` through the hub to a node and gets real content.
- Discovery reports the node's `files` connector.

*Status:* not started.

## Phase 4 — binary wiring + close out
