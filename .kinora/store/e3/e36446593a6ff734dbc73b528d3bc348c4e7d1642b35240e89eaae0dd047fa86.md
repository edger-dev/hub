# Task — live session messaging

Implement `hub::spec::session-messaging`: authenticated live session
registration, peer-aware discovery, and acknowledged one-hop message delivery.

## Done when

- Two real shims on different hubs register and appear in each other's session
  listings over one explicitly dialled peer relationship.
- A message and its reply cross that relationship with unspoofed qualified
  sender identities and explicit delivery acknowledgement.
- Unknown, disconnected, and unauthenticated targets fail visibly; reconnect
  cleanup cannot remove a newer registration.
- Existing node, consumer, and peer tests remain green with zero warnings.
- Deployment/API documentation describes live-only scope and qualified names.
