# Finding — a vox domain error arrives in `VoxError::User`, not as text

**Observed** (vox 0.10.0-rc.5, wiring the hub's `route` in M3).

**This corrects an earlier assumption.** A `#[vox::service]` method declared
`async fn f(..) -> Result<T, E>` does *not* give the caller `Result<Result<T, E>,
_>`; the generated client returns `Result<T, VoxError<E>>`. Because that reads as
a single `Result`, it is easy to conclude the domain error was flattened to a
string — it is not. The callee's `E` is carried **structurally** in
`VoxError::User(Box<E>)`, alongside transport variants (`UnknownMethod`,
`Cancelled`, `ConnectionClosed`, …).

So the right client-side shape is:

```rust
client.call(..).await.map_err(|e| match e {
    vox::VoxError::User(domain) => /* the callee's own error, intact */,
    other                       => /* a transport-level failure */,
})
```

**Why it matters.** Stringifying the error (`format!("{e:?}")`) throws away a
structured error the wire already preserved, and it silently erases contracts
built on that distinction — here, `RouteError::Hub` vs `RouteError::Node`, which
tells a consumer whether to refresh its topology or surface a refusal. Both the
hub's `route` and the node's `register` now recover the typed error.
