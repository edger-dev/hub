# Spec — the hub serves WebSocket connections beside TCP

**Contract.** With `HUB_WS_ADDR` set, the hub binds a WebSocket listener at that
address in addition to its existing TCP listeners. Each accepted socket is
upgraded to WebSocket and served by the same registry, routing, and
connection-authentication path as TCP. Dropping the listener shuts down its
live connections. TCP behavior is unchanged when the variable is absent.

**Deployment boundary.** The built-in listener is plain WebSocket on a local or
private address. A public deployment terminates TLS at Cloudflare or another
proxy and forwards the HTTP WebSocket upgrade to this listener. The hub's
`HUB_AUTH_TOKEN` remains mandatory for protected operation.

**Why.** Vox already has message-framed WebSocket links. Reusing the hub's
existing connection handler adds remote HTTPS/WSS reach without a second hub,
Worker, persistence layer, or routing implementation.

**Rejected.** Replacing TCP, a separate WebSocket-only hub state, terminating
TLS inside this first listener, and weakening connection authentication for
WebSocket clients.

**Escape hatch.** Native `WssListener` support can be added later for direct TLS
without changing the transport contract.
