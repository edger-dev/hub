# Spec — nodes dial WebSocket hubs without changing reconnect semantics

**Contract.** A node's `HUB_ADDR` accepts `ws://` and `wss://` URLs in addition
to bare and `tcp://` addresses. WebSocket nodes open Vox WebSocket links and
use the same `NodeService` callback, registration, connection token, and
reconnect loop as TCP nodes. A down hub yields no link and is retried with the
existing backoff; an unsupported scheme remains a configuration error. TCP
behavior is unchanged.

**Deployment.** `wss://` is for direct public TLS endpoints such as a VPS with
Caddy or Nginx. `ws://` is for local/private tests and proxies. The first
version uses Vox's standard WebSocket handshake without Cloudflare Access
service-token headers; Kudo's sending shim already supports those separately.

**Why.** A VPS-hosted hub becomes reachable by every home node over the same
public HTTPS endpoint as remote shims, with no SSH or Cloudflare client
forwarder. The generic reconnect tests already establish transport-independent
recovery.

**Rejected.** Replacing TCP, duplicating node registration policy in the
WebSocket dialer, requiring peer-hub WSS for a single-hub deployment, and
silently treating malformed addresses as temporary outages.

**Escape hatch.** Cloudflare Access credentials can be added to the node
handshake later if a node must cross an Access-protected hostname.
