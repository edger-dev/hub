# Spec — a connector owns its payload; the hub never inspects it

**Contract.** A `RoutedCall` carries a connector id, a method name, and an opaque
`payload: Vec<u8>`. The hub routes on the *addressing* fields only and never
decodes, validates, or rewrites the payload. Encoding is a private agreement
between a connector and its callers; the node dispatches to the addressed
connector, which owns the codec.

**Chosen.** Opaque bytes with per-connector encoding. A new connector — or a new
method, or a changed payload shape — ships without touching the hub or the
protocol crate, which is exactly what "the hub presents a stable protocol; what
is behind it is swappable" requires.

**Rejected.** A hub-typed payload union (one enum of every connector's request
type). It drags every connector's vocabulary into the shared protocol, so the hub
must be rebuilt and redeployed to add a capability it does not care about, and
two nodes could not run different connector versions.

**Escape hatch.** A capability that genuinely needs hub involvement (routing on
payload content, hub-side policy) should become a first-class protocol method
rather than smuggling semantics into the opaque bytes.
